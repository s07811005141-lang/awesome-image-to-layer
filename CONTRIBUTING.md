# Contribution Guidelines

Thanks for helping improve this list. To add, fix or remove an entry, open a pull request that edits `README.md`.

## Adding an entry

1. Pick the section that fits best. If nothing fits, explain why in the pull request and suggest a new section.
2. Add one line in this format:

   ```markdown
   - [Name](https://link) - Short description.
   ```

3. Mention in the pull request what the resource does and why it belongs on a list about turning flat images into editable layers.

## Rules

- **No dead links.** Open every link before submitting. Link to the official source: the project repository, the arXiv abstract page (`https://arxiv.org/abs/...`), or the official product or documentation page. No link shorteners, affiliate or tracking links.
- **One line per entry.** One resource per line, no line breaks inside an entry.
- **Description format.** Start with a capital letter, end with a period, keep it short and factual. No marketing words such as "best", "revolutionary" or "the only". Say if a tool is paid, gated or limited to non-commercial use.
- **Alphabetical order** within each section and subsection (case-insensitive). The one exception is the maintainer's pick, which stays at the top of Online tools.
- **Papers** use the paper title as the name and end the description with the year, or the venue and year, for example `(ICCV 2025)`.
- **One entry per pull request** is preferred, so each can be reviewed on its own.
- **Relevant only.** Resources must help with splitting images into layers, filling hidden areas, or reading and writing layered files. General image editors or AI tools without a layer-related feature will not be added.
- Entries whose links stop working, or whose projects are withdrawn, may be removed.
